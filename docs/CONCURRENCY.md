# Lock-free SPSC: сеть → планировщик без мьютексов

## Зачем одна очередь и почему SPSC

Поток сети единственный производитель, поток планировщика единственный
потребитель. SPSC — минимальная корректная модель: атомарные индексы
без CAS-циклов, отсутствие contention, гарантированная верхняя граница
работы на операцию (две атомарные загрузки + две атомарные записи).

## Алгоритм

```cpp
template <typename T, size_t Cap>
requires std::is_trivially_copyable_v<T> && ((Cap & (Cap - 1)) == 0) && (Cap >= 2)
struct SpscRing {
    // ...
private:
    alignas(64) std::atomic<u64> head_{0};   // принадлежит consumer'у
    alignas(64) std::atomic<u64> tail_{0};   // принадлежит producer'у
    alignas(64) std::array<T, Cap> buf_{};
};
```
- Индексы **монотонные** `uint64` (без обёртывания): `full ⇔ tail − head == Cap`,
  `empty ⇔ head == tail`. Не нужны ни резервные слоты, ни флаги occupied.
- `try_push`: `head.load(acquire)` (свежесть освобождённых слотов), запись в слот,
  `tail.store(t+1, release)` — **release** публикует записанные данные;
  `tail.load(relaxed)` легален: tail изменят только producer.
- `try_pop`: `tail.load(acquire)` — видны все опубликованные слоты; копирование;
  `head.store(h+1, release)` освобождает слот производителю.
- Разделение `head`/`tail`/`buf` разными кэш-линиями (`alignas(64)`) — нет
  ложного разделения (false sharing) между ядрами.

## Корректность

Классическая пара release/acquire: consumer, прочитавший обновлённый `tail`,
видит полностью записанный слот (happens-before через store-release/pop-acquire
в модели памяти C++). Producer аналогично видит освобождение слотов через
acquire-загрузку `head`. Потерянных дубликатов нет: слот переходит из
«писательский» в «читательский» ровно одной записью `tail`.

`FrameMsg` объявлен `alignas(64)` и trivially copyable
(`static_assert(std::is_trivially_copyable_v<ParsedFrame>)`) — копия слота
атомарна по построению на x86-64 при поштучном копировании POD.

## Что это доказывает, а что нет

- Доказано тестом: 20 000…100 000 кадров через границу потоков, порядок `seq`
  сохранён, ни одного дедлока (цикл завершается по исчерпании потока),
  **TSan не нашёл ни одной гонки**.
- Не доказано формально: используется стандартная, хорошо изученная схема
  (монотонный индексный контур Lamport в современной формулировке); при изменении
  Cap/структуры тест переигрывается обязателен.

## Дисциплина памяти

`push`/`pop` не аллоцируют: буфер — `std::array` внутри объекта очереди,
объект размещается на стеке потока планировщика. Детектор аллокаций
(подмена глобального `operator new` в тестовой сборке) подтверждает,
что весь цикл «парсинг → очередь → планирование» не трогает кучу.
