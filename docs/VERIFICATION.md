# Верификация

## Стенд

| Параметр | Значение |
|---|---|
| Компилятор | g++ 13.3.0 (Ubuntu 24.04), clang в стенде отсутствует |
| Флаги | `-std=c++20 -O2 -Wall -Wextra -Wpedantic -Wshadow -Werror` |
| CPU | Intel Xeon E5-2699 v3 @ 2.30 GHz (36 потоков) |
| Ядро Linux | 7.0 |

## Три сборки

```bash
make all
./build/test_plain                     # полный стресс 100k, alloc-guard ВКЛ
./build/test_asan                      # ASan+UBSan, 20k кадров
setarch $(uname -m) -R ./build/test_tsan   # TSan, 20k кадров
```

`setarch -R` (отключение ASLR) обходит известную поломку TSan-рантайма на
новых ядрах: `FATAL: ThreadSanitizer: unexpected memory mapping`. Без этого
TSan падает до начала тестов; проблема окружения, не кода.

## Результат (2026-10-18)

```text
[test] protocol: CRC-16-CCITT + roundtrip + битый пакет
[test] scurve: jerk-limited инварианты (3 ветки: cruise/промежуточный/треугольный)
[test] geometry: AABB/OBB пересечение отрезка с боксом
[test] collision: конфликт в зоне → mitigation, робот A нетронут, цикл не остановлен
[test] jobshop: монотонные ресурсы станков, без перекрытий
[test] spsc stress: producer/consumer, 50% битых кадров, порядок seq, no-alloc
  stress: N=100000 ok=50000 crc=50000 planned=35 rejected=49965
=== RESULT: PASS (0 failures) ===
```

Выход: `test_plain` 0, `test_asan` 0, `test_tsan` 0. Бухгалтерия стресса
сходится: `crc` (отброшено по CRC) `+ ok` (принято) `= N`; внутри принятых
`planned + rejected = ok`. Ни одной потерянной единицы — учёт не зависит от
таймингов потоков.

## Матрица приёмки

| Требование | Как доказано | Вердикт |
|---|---|---|
| Нулевые аллокации после init | `operator new` подменён броском; 100k кадров — ни одного срабатывания; guard-тест требует ровно 0 аллокаций | PASS |
| CRC + отсев битых пакетов | `static_assert` эталона 0x29B1; round-trip; порча байта → `CrcError` и кадры нет в планировщике | PASS |
| Q16.16, побайтовая сборка без UB | ASan+UBSan exit 0 на всей нагрузке | PASS |
| Конфликт траекторий → пересчёт S-curve | AABB и OBB-зоны: окна occupancy не пересекаются, `mitigation ∈ {Respeed, DelayStart}` | PASS |
| Робот с приоритетом нетронут | снапшот `RobotCell` до/после: идентичны `t_start`, `D`, `T_total`, `v_peak`, путь | PASS |
| Без полной остановки цикла | `vel` жертвы в середине окна зоны > 0.1 м/с | PASS |
| Отсутствие гонок/дедлоков | TSan exit 0, 2 потока, 20k кадров; стресс завершается сам | PASS |
| Job-Shop: операции на станках не пересекаются | монотонность `busy_until`, старт `max(busy, ready)` на 6 операциях | PASS |

## Кейсы: что поймала верификация (код генерировался моделью)

Четыре дефекта, все — не ошибки компиляции, а логика. Каждый найден
прогоном, а не чтением:

| № | Дефект | Симптом | Метод нахождения |
|---|---|---|---|
| 1 | OBB slab: `tb = (h + p·a)/(d·a)` вместо `(h − p·a)/(d·a)` | ложные «miss» у повёрнутой зоны, симметричные окна `[−0.75, 0.75]` | Python-порт алгоритма как оракул формул |
| 2 | S-curve: бисекция «укоротить jerk-фазу до vmax» | вырожденный профиль `v_peak = 0`, `T_total = 0` | вывод инвариантов `pos(T_total) ≠ D`; переписано на 3 замкнутые ветки |
| 3 | `add_robot` не задавал начальный `tcp` | путь робота 2 = `√109` вместо 10, провал `pos(T_total) − 10 = 0.440306509` | одноразовый дамп траектории (`seg[]` целиком) |
| 4 | Стресс-генератор слал `robot_id = 0`, которого нет в конфигурации | `rejected` выше ожидаемого | сверка счётчиков `planned/rejected` |

Вывод для методологии: правдоподобие кода ≠ корректность. Модель уверенно
пишет формулы и ломает граничные условия и конфигурацию окружения — ловится
только внешней верификацией (санитайзеры + независимый оракул + бухгалтерия
событий).
